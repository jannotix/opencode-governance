# OpenCode Governance v3.3 Executor Failover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete optional, work-class-aware Executor failover using isolated Git worktrees without exposing any real provider, model, subscription, or personal routing configuration in the repository.

**Architecture:** The installer validates generic routing profiles and renders hidden Executor route aliases. Architect orchestration uses deterministic cross-platform helpers to select a route, create a detached worktree at the frozen target, restart the complete Executor from the same canonical packet, discard failed attempts, finalize a verified binary patch, and promote only when the real worktree remains unchanged and non-overlapping. Normal evidence, review, commit, and external-action gates remain unchanged.

**Tech Stack:** PowerShell 7/Windows PowerShell-compatible scripts, Bash, Python 3 on Unix, Git linked worktrees, OpenCode agent and command templates, GitHub Actions.

## Global Constraints

- Keep the repository provider- and model-agnostic; use only synthetic `test/...` identifiers and generic family names in committed examples and tests.
- Preserve seven public governance agents and twelve public commands.
- Preserve the single-writer invariant: only the accepted Executor attempt authors application source or approved project documentation.
- Never continue partial Executor output; every fallback restarts from the same frozen target and canonical packet hash.
- Never automatically push, merge, deploy, publish, rollback, or use production credentials.
- Executor failover remains optional; legacy single-model installation must continue to work.
- Windows must not require Python; Unix may use the repository's existing Python 3 helper path.
