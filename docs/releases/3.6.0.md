# OpenCode Governance 3.6.0

## Governance Authority, Memory and Evidence Runtime

This release completes the planned 3.4.5, 3.5.0 and 3.6.0 capability roadmap as one cumulative runtime overlay over the routing-compatible 3.4.4 base.

### 3.4.5 capabilities

- deterministic scenario contracts for all twelve `/ai-*` commands;
- a loopback OpenAI-compatible runner that can drive a real OpenCode process without commercial model calls;
- typed, executable continuation instead of narrative retry instructions;
- explicit refusal of automatic push, merge, deployment, publication and production rollback.

### 3.5.0 capabilities

- immutable `workspace`, `staged`, `commit` and `base-diff` candidate projections;
- content-bound governance approval receipts;
- live post-apply, pre-commit, pre-push, pre-PR and release receipt validation;
- an explicit project-scoped Git pre-commit gate that validates the exact staged receipt without a model call;
- risk-derived review lenses without reducing independent reviewers.

### 3.6.0 capabilities

- Final-Reviewer-governed local engineering memory;
- progressive memory disclosure, supersession and review lifecycle;
- owner-authorized promotion of recurring validated lessons into project policy;
- exact dependency-bound evidence reuse;
- transactional cross-platform runtime installation with rollback on post-mutation failure;
- exact managed-tool and managed-section integrity verification;
- conservative uninstall that preserves unrelated local tools, prompt content, backups and memory data.

The release remains provider- and model-agnostic. Existing local routes, variants, fallback order, work classes, authentication and reviewer independence remain unchanged. The runtime receipt never authorizes an external action.
