# OpenCode Governance v3.2 — Architect Phase Failover

**Status:** Approved for implementation  
**Date:** 2026-07-28  
**Base:** OpenCode Governance 3.1.0  
**Target:** 3.2.0

## Purpose

Provide real automatic failover for the top-level Architect model used by Architect, governed Build and governed Plan without pretending that a failed top-level agent can delegate to itself.

## Runtime constraint

OpenCode binds a model to an agent/command invocation. A subagent alias solves reviewer failover because the still-running Architect can select another reviewer. It cannot solve failure of the top-level Architect because no outer governance model remains to catch the error.

v3.2 therefore uses a deterministic external runner around `opencode run`. The runner selects the concrete Architect route, invokes one governance command, classifies failure, restores governance state and starts a new OpenCode attempt with the next route.

No hidden `architect-fallback-*` agents are generated.

## Supported commands

Automatic Architect failover is enabled only for commands that do not authorize application-source or project-documentation writes:

```text
ai-init
ai-audit
ai-discover
ai-plan
```

`ai-workflow`, governed Build execution, `ai-execute`, `ai-review` and `ai-release` are not eligible for top-level automatic restart in v3.2 because a failed full workflow may already contain Executor or review side effects. They stop with:

```text
TOP_LEVEL_FAILOVER_UNSAFE_AFTER_EXECUTION_BOUNDARY
```

The normal v3.1 reviewer/final failover remains active inside all workflows.

## Runner

Cross-platform entry points:

```text
scripts/run-governed.ps1
scripts/run-governed.sh
```

Required inputs:

```text
PROJECT_DIR
COMMAND
ARGUMENTS
ROUTING_CONFIG
```

The runner uses the Architect primary plus ordered Architect fallbacks from the validated routing profile. It executes:

```text
opencode run
  --dir <project>
  --agent architect
  --model <provider/model>
  --variant <concrete variant when configured>
  --command <governance command>
  --format json
  <arguments>
```

Each fallback starts a new process and a new role attempt. It never continues a partial response or session.

## Governance-state transaction

Before each attempt, the runner creates a private temporary snapshot outside the project containing the complete current `.ai/**` tree and a SHA-256 manifest. If `.ai/**` does not exist, the checkpoint records `PREVIOUS_AI_STATE: ABSENT`.

The checkpoint records:

```text
RUN_ATTEMPT_ID
COMMAND
ARGUMENTS_SHA256
ROUTE_AGENT
SELECTED_MODEL
SELECTED_VARIANT
MODEL_FAMILY
ATTEMPT_NUMBER
PREVIOUS_AI_STATE
PRE_ATTEMPT_AI_TREE_SHA256
CHECKPOINT_PATH
CHECKPOINT_COMPLETE: YES
```

The snapshot excludes no governance file. It is stored outside the repository and is removed after successful completion.

## Failure recovery

On an eligible failure:

1. reject all partial stdout/stderr as non-authoritative evidence;
2. classify the error from structured JSON events, exit code and bounded stderr patterns;
3. stop if the classification is ambiguous or ineligible;
4. remove the failed attempt's `.ai/**` tree;
5. restore the complete pre-attempt `.ai/**` snapshot, or restore absence;
6. verify the restored tree hash;
7. keep project source and documentation unchanged;
8. select the next eligible Architect route;
9. restart the complete command in a new process.

If source or project documentation changed despite the Architect permission boundary, or `.ai/**` cannot be restored exactly, return:

```text
ARCHITECT_FAILOVER_BLOCKED
HUMAN_RECOVERY_REQUIRED
```

The runner records only non-secret attempt metadata in a temporary log. Failed model output is never copied into `.ai/**`.

## Failure classification

Eligible automatic failures:

```text
PROVIDER_UNAVAILABLE
RATE_LIMIT
PLAN_QUOTA_EXHAUSTED
MODEL_RETIRED
MODEL_TEMPORARILY_UNAVAILABLE
BOUNDED_TIMEOUT
```

Automatic fallback is forbidden for:

```text
AUTHENTICATION_FAILED
INVALID_MODEL_CONFIGURATION
CONTEXT_OVERFLOW
TOOL_PERMISSION_DENIED
SAFETY_REFUSAL
MALFORMED_REQUEST
INVALID_PACKET
VALIDATION_FAILURE
LOW_QUALITY_OUTPUT
UNCLASSIFIED_FAILURE
```

Provider/rate/quota failures prefer the same model family through another provider. Model retirement or global family unavailability skips the failed family.

## Sticky attempt and primary re-entry

Once a fallback process starts, it runs to completion or failure. Availability of the primary does not interrupt it.

Primary becomes eligible again only on the next independent runner invocation after `Retry-After`, an authoritative quota reset, or the configured cooldown. It never reruns the just-completed command merely because quota returned.

## Build and Plan behavior

- Architect commands use the runner directly.
- Governed Plan is fully supported through `ai-plan`.
- Governed Build may use the runner only for its pre-execution planning/discovery stage. Full `ai-workflow` automatic top-level failover remains blocked after the execution boundary.

This is a deliberate safety restriction, not an implementation omission.

## Routing profile

v3.2 permits Architect fallbacks in the existing routing profile. They are consumed by the external runner and are not rendered as subagent aliases.

The installer continues to render only reviewer/final hidden aliases. The non-secret routing manifest retains Architect candidates for the runner.

Every candidate requires concrete:

```text
model
variant or provider_default
variant_policy
model_family
priority for fallbacks
only_on
```

## Compatibility

- Legacy single-model installation remains supported.
- v3.1 reviewer-only profiles remain valid.
- Architect failover activates only when `architect` is listed in `settings.enabled_roles`.
- Seven public governance agents and twelve commands remain unchanged.
- No Executor failover is activated in v3.2.
- No plugin or mandatory runtime dependency is introduced.

## Acceptance criteria

1. Existing v3.1 profiles install unchanged.
2. A v3.2 profile may include Architect fallbacks without generating Architect aliases.
3. Reviewer/final aliases remain exact and independently verified.
4. The runner rejects unsafe commands.
5. The runner rejects unresolved variants and unsupported error classes.
6. A simulated eligible primary failure selects the correct fallback.
7. Same-family alternate providers are preferred for provider/quota failures.
8. Model retirement skips the failed family.
9. `.ai/**` is restored byte-for-byte before fallback.
10. Source or documentation changes block failover.
11. Partial output is never persisted as governance evidence.
12. Active fallback is never preempted by primary recovery.
13. Primary is reconsidered only on a later invocation after cooldown.
14. Windows and Linux CI cover success, eligible failover, ineligible failure, restore verification and unsafe-command rejection.
