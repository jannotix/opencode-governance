# OpenCode Governance v3.3 — Isolated Executor Failover

**Status:** Approved for implementation  
**Date:** 2026-07-28  
**Base:** OpenCode Governance 3.2.0  
**Target:** 3.3.0

## Purpose

Add real automatic failover for Executor while preserving the single-writer invariant and preventing a failed model from leaving partial application or project-documentation changes in the real worktree.

## Architecture

Every Executor attempt runs in a detached linked Git worktree created under:

```text
.ai/executor-worktrees/<EXECUTOR_ATTEMPT_ID>/
```

The attempt starts from the same `FROZEN_TARGET_SHA`. The hidden fallback alias receives the same `EXECUTION_PACKET.md`, but the packet additionally contains:

```text
EXECUTION_ROOT
EXECUTOR_ATTEMPT_ID
SELECTED_ROUTE_AGENT
SELECTED_MODEL
SELECTED_VARIANT
MODEL_FAMILY
WORK_CLASS
PACKET_SHA256
FROZEN_TARGET_SHA
```

Executor writes application source and approved project documentation only inside `EXECUTION_ROOT`. It never writes the real project worktree during an attempt.

## Routing

v3.3 enables `executor` in `settings.enabled_roles` and generates hidden aliases:

```text
executor-fallback-1
executor-fallback-2
executor-fallback-3
```

Candidates may narrow eligibility with:

```text
work_classes:
  - PATCH
  - BOUNDED_FEATURE
```

Allowed work classes are:

```text
PATCH
BOUNDED_FEATURE
MAJOR_FEATURE
EXISTING_PRODUCT_EVOLUTION
NEW_PRODUCT
HIGH_RISK_CHANGE
```

Selection rules:

1. reject ineligible or unclassified failures;
2. never select an attempted or cooling-down route;
3. filter by `only_on` and `work_classes`;
4. for provider/rate/quota failures prefer the same model family through another provider;
5. for `MODEL_RETIRED` or global family unavailability skip the failed family;
6. choose the lowest remaining priority;
7. once a fallback attempt begins, never preempt it;
8. reconsider primary only on a later task after cooldown.

## Attempt lifecycle

A deterministic helper manages the attempt:

```text
scripts/executor-attempt.ps1
scripts/executor-attempt.sh
```

Operations:

```text
select
prepare
finalize
promote
discard
```

### `select`

Reads the installed routing manifest and returns one eligible route for the supplied work class and failure context.

### `prepare`

- verifies the project is a Git repository;
- verifies the frozen target exists;
- creates a detached linked worktree under `.ai/executor-worktrees/`;
- records the real worktree Git state and hashes;
- creates an attempt manifest under the existing task evidence tree;
- returns the execution root.

### `finalize`

Inside the isolated worktree:

- rejects changes under `.ai/**` or `.git/**`;
- stages all isolated changes only in the temporary worktree index;
- creates a binary patch;
- records changed paths and patch SHA-256;
- verifies the Executor report contains matching identifiers and `REPORT_COMPLETE: YES`;
- never applies the patch to the real worktree.

### `promote`

Before promotion:

- verifies the real `HEAD` still equals the frozen target;
- verifies the real worktree status is unchanged from `prepare`;
- rejects overlap between pre-existing dirty paths and proposed patch paths;
- runs `git apply --check --binary`;
- applies the exact verified patch;
- verifies every applied path matches the patch result;
- records promotion evidence;
- removes the isolated worktree.

If any condition fails, promotion stops without retrying another model.

### `discard`

Removes the isolated worktree and attempt-created temporary artifacts. No application change is copied to the real worktree.

## Pre-existing user changes

Unrelated dirty changes may exist only when:

- their exact status remains unchanged during the attempt;
- none overlaps a proposed patch path;
- patch application succeeds without modifying them.

Overlapping or newly changed real-worktree paths return:

```text
EXECUTOR_FAILOVER_BLOCKED
HUMAN_RECOVERY_REQUIRED
```

## Failure handling

Eligible failures remain:

```text
PROVIDER_UNAVAILABLE
RATE_LIMIT
PLAN_QUOTA_EXHAUSTED
MODEL_RETIRED
MODEL_TEMPORARILY_UNAVAILABLE
BOUNDED_TIMEOUT
```

Ineligible failures, invalid packets, missing reports, hash mismatches, source changes outside the isolated worktree or promotion conflicts fail closed.

On an eligible Executor model failure:

1. classify the error;
2. discard the failed isolated worktree;
3. preserve only non-secret attempt metadata;
4. select the next eligible route;
5. create a fresh isolated worktree at the same frozen target;
6. restart the complete Executor role from the same packet.

Partial output and partial source changes are never authoritative.

## Single-writer invariant

Executor remains the only agent that authors application/project-documentation changes. The deterministic promotion helper copies only the exact patch authored and completed by the accepted Executor attempt. Architect cannot edit, modify or augment that patch.

## Review

After promotion, normal Evidence-Driven Verification, Operational Assurance, dual review and Final Reviewer adjudication run against the real worktree. Promotion is not validation and does not authorize commit or push.

Exact provider/model IDs and concrete variants remain locally resolved configuration.

## Compatibility

- Legacy single-model installation remains supported.
- v3.1 reviewer/final hidden routes remain supported.
- v3.2 Architect external runner remains supported.
- Seven public governance agents and twelve commands remain unchanged.
- Executor failover is optional and disabled when no Executor fallbacks are configured.
- No mandatory external dependency beyond existing Git, PowerShell on Windows and Python 3 used by the Unix installer/helpers.

## Acceptance criteria

1. Valid Executor routes render hidden aliases with exact manifest reconciliation.
2. Work-class filters select Qwen Plus for bounded work and Qwen Max for major/high-risk work.
3. Same-family MiMo alternate provider is preferred for provider/quota failure.
4. A failed attempt can modify its isolated tree without changing the real worktree.
5. Discard removes all failed partial changes.
6. A fallback starts from the same frozen target and packet.
7. Finalize rejects `.ai/**`, incomplete reports and mismatched hashes.
8. Promotion rejects changed real HEAD/status or overlapping dirty paths.
9. Verified patch promotion preserves unrelated dirty changes.
10. Review and commit gates remain unchanged after promotion.
11. Windows and Linux CI cover selection, prepare, discard, finalize, promotion, overlap blocking and conservative uninstall.
