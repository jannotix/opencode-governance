# OpenCode Governance v3.3 — Isolated Executor Failover

**Status:** Approved for implementation  
**Date:** 2026-07-28  
**Base:** OpenCode Governance 3.2.0  
**Target:** 3.3.0

## Purpose

Add optional automatic failover for Executor while preserving the single-writer invariant and preventing a failed route from leaving partial application or project-documentation changes in the real worktree.

The design is provider- and model-agnostic. Exact providers, model IDs, variants, subscriptions and personal routing preferences are local untracked configuration and are not part of this repository.

## Architecture

Every routed Executor attempt runs in a detached linked Git worktree created under:

```text
.ai/executor-worktrees/<EXECUTOR_ATTEMPT_ID>/
```

The attempt starts from the same `FROZEN_TARGET_SHA`. The selected public or hidden Executor route receives the same frozen canonical execution packet plus:

```text
EXECUTION_MODE: ISOLATED_FAILOVER
EXECUTION_ROOT
EXECUTOR_ATTEMPT_ID
SELECTED_ROUTE_AGENT
SELECTED_MODEL
SELECTED_VARIANT
MODEL_FAMILY
WORK_CLASS
PACKET_SHA256
FROZEN_TARGET_SHA
```

Executor writes application source and approved project documentation only inside `EXECUTION_ROOT`. It may read canonical governance state from the real project as immutable authority but never edits application or documentation paths in the real worktree during an attempt.

## Routing

v3.3 allows `executor` in `settings.enabled_roles` and generates hidden aliases from configured fallback priorities:

```text
executor-fallback-1
executor-fallback-2
executor-fallback-N
```

Candidates may narrow eligibility with:

```json
{
  "work_classes": [
    "PATCH",
    "BOUNDED_FEATURE"
  ]
}
```

Allowed work classes:

```text
PATCH
BOUNDED_FEATURE
MAJOR_FEATURE
EXISTING_PRODUCT_EVOLUTION
NEW_PRODUCT
HIGH_RISK_CHANGE
```

Selection rules:

1. reject ineligible or unclassified failures;
2. never select the failed, attempted or cooling-down route;
3. filter by `only_on` and `work_classes`;
4. for provider, rate-limit or quota failures prefer the same model family through another configured provider;
5. for `MODEL_RETIRED` or global family unavailability skip the failed family;
6. choose the lowest remaining priority;
7. never preempt an active fallback attempt;
8. reconsider primary only on a later invocation after cooldown.

## Installed helpers

The installer copies deterministic helpers into the local OpenCode configuration directory:

```text
opencode-governance-tools/executor-attempt.ps1
opencode-governance-tools/executor-attempt.sh
```

The routing manifest records the exact managed tool paths. Uninstall removes only those exact managed files and refuses unknown paths.

Operations:

```text
select
prepare
finalize
promote
discard
```

### `select`

Reads the installed or supplied routing manifest and returns one eligible route for the supplied work class and failure context.

### `prepare`

- verifies the project is a Git worktree;
- verifies the frozen target exists and equals real `HEAD`;
- verifies the selected route supports the work class;
- creates a detached linked worktree under `.ai/executor-worktrees/`;
- records the real worktree Git status, dirty paths and content fingerprints;
- creates an attempt manifest under the existing task evidence tree;
- returns the isolated execution root.

### Executor delegation

Architect delegates exactly once to the selected route with the frozen packet and attempt metadata. The route must:

- use `EXECUTION_ROOT` for every source/documentation write and mutating command;
- never write `.ai/**` or `.git/**` inside the isolated worktree;
- never commit or copy changes to the real worktree;
- return a complete machine-readable report with matching attempt, packet and frozen-target identifiers.

A prior attempt, partial output or sibling route is never input to the next attempt.

### `finalize`

Inside the isolated worktree the helper:

- rejects changes under `.ai/**` or `.git/**`;
- rejects an empty implementation patch;
- stages isolated changes only in the temporary worktree index;
- creates a binary-safe patch directly through Git;
- records changed paths and patch SHA-256;
- verifies the accepted Executor report contains matching identifiers and `REPORT_COMPLETE: YES`;
- never applies the patch to the real worktree.

### `promote`

Before promotion the helper:

- verifies real `HEAD` still equals the frozen target;
- verifies real Git status and dirty-path content fingerprints are unchanged from `prepare`;
- rejects overlap between pre-existing dirty paths and proposed patch paths;
- verifies the stored patch hash;
- runs `git apply --check --binary`;
- applies the exact verified patch;
- verifies the patch can be reversed cleanly;
- records promotion evidence;
- removes the isolated worktree.

Any failure stops promotion without selecting another model.

### `discard`

Removes the isolated worktree and attempt-created patch artifact. For an eligible model/provider failure it records bounded cooldown state. No application or project-documentation change is copied to the real worktree.

## Pre-existing user changes

Unrelated dirty changes may exist only when:

- their exact status and content fingerprints remain unchanged during the attempt;
- none overlaps a proposed patch path;
- patch application succeeds without modifying them.

Overlapping, newly changed or silently modified dirty paths return:

```text
EXECUTOR_FAILOVER_BLOCKED
HUMAN_RECOVERY_REQUIRED
```

## Failure handling

Eligible failures:

```text
PROVIDER_UNAVAILABLE
RATE_LIMIT
PLAN_QUOTA_EXHAUSTED
MODEL_RETIRED
MODEL_TEMPORARILY_UNAVAILABLE
BOUNDED_TIMEOUT
```

Ineligible failures include invalid configuration, authentication errors, invalid packets, plan conflicts, permission or safety refusals, context overflow, malformed or incomplete reports, validation defects, hash mismatches, changed real state and promotion conflicts.

On an eligible Executor route failure:

1. classify the error;
2. discard the failed isolated worktree;
3. preserve only non-secret attempt metadata;
4. mark the route attempted and apply bounded cooldown;
5. select the next eligible route;
6. create a fresh isolated worktree at the same frozen target;
7. restart the complete Executor role from the same canonical packet.

Partial output and partial source changes are never authoritative.

## Single-writer invariant

Executor remains the only agent that authors application and approved project-documentation changes. The deterministic promotion helper copies only the exact patch authored and completed by the accepted Executor attempt. Architect may write governance evidence under real `.ai/**` but cannot edit, modify or augment the promoted patch.

## Review

After promotion, Architect persists the accepted Executor report and reruns required Evidence-Driven Verification and Operational Assurance against the real worktree. Independent dual review and Final Reviewer adjudication remain mandatory. Promotion is not validation and does not authorize commit, push, merge or deployment.

## Compatibility

- Legacy single-model installation remains supported.
- v3.1 Reviewer and Final Reviewer hidden routes remain supported.
- v3.2 Architect external runner remains supported.
- Seven public governance agents and twelve commands remain unchanged.
- Executor failover is optional and disabled when Executor is not enabled in routing settings.
- Windows requires existing Git and PowerShell; Unix installer/helpers continue to use existing Git, Bash and Python 3.
- No new provider, model, account, credential or paid service is required by the repository.

## Acceptance criteria

1. Valid generic Executor routes render hidden aliases with exact manifest reconciliation.
2. Work-class filters select only eligible bounded or major/high-risk routes.
3. Same-family alternate-provider routes are preferred for provider, quota and rate-limit failures.
4. Retired or globally unavailable families are skipped.
5. A failed attempt can modify its isolated tree without changing the real worktree.
6. Discard removes failed partial changes and attempt patch artifacts.
7. A fallback starts from the same frozen target and packet.
8. Finalize rejects `.ai/**`, empty changes, incomplete reports and mismatched identifiers.
9. Windows creates binary patches without text-pipeline corruption.
10. Promotion rejects changed real `HEAD`, status, dirty-path content or overlapping paths.
11. Verified patch promotion preserves unrelated dirty changes.
12. `/ai-execute` and `/ai-workflow` perform bounded isolated recovery only when routing enables Executor failover.
13. Review, commit and external-action gates remain unchanged after promotion.
14. Windows and Linux CI cover installation, route selection, prepare, discard, finalize, promotion, conflict blocking and conservative uninstall.
15. No real provider, model or personal routing configuration is committed.
