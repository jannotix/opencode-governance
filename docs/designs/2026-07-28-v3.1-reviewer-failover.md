# OpenCode Governance v3.1 — Reviewer Role Failover

**Status:** Approved for implementation  
**Date:** 2026-07-28  
**Base:** OpenCode Governance 3.0.2  
**Target:** 3.1.0

## Purpose

Provide real provider/model failover for Implementation Reviewer, Architecture/Security Reviewer and Final Reviewer without weakening frozen-target review, reviewer independence, evidence freshness or the seven public governance authorities.

## Native execution mechanism

OpenCode assigns one static model and optional variant to an agent. The Task tool cannot dynamically choose a model. v3.1 therefore renders hidden internal subagent aliases for each configured fallback candidate.

Examples:

```text
reviewer-fallback-1
reviewer-architecture-fallback-1
final-reviewer-fallback-1
```

Aliases use `mode: subagent` and `hidden: true`. They are routing transports for an existing authoritative role, not additional governance authorities. They inherit the canonical role prompt and permissions and cannot delegate.

Public contract remains:

```text
PUBLIC_GOVERNANCE_AGENTS: 7
PUBLIC_COMMANDS: 12
```

## Routing configuration

A routing profile is optional. Legacy single-model installation remains supported.

Every executable route candidate requires:

```text
model
variant
model_family
priority
```

`model` must be a concrete `provider/model` identifier. `variant` must be a concrete supported value or null. The literal value `highest_supported` is not executable because OpenCode exposes model-specific variants and provides no reliable non-interactive highest-variant resolver. A profile may record `variant_policy: highest_supported`, but installation requires the locally resolved concrete `variant`.

## Eligible automatic triggers

```text
PROVIDER_UNAVAILABLE
RATE_LIMIT
PLAN_QUOTA_EXHAUSTED
MODEL_RETIRED
MODEL_TEMPORARILY_UNAVAILABLE
BOUNDED_TIMEOUT
```

Fallback is forbidden for:

```text
AUTHENTICATION_FAILED
INVALID_MODEL_CONFIGURATION
CONTEXT_OVERFLOW
TOOL_PERMISSION_DENIED
SAFETY_REFUSAL
MALFORMED_REQUEST
INVALID_PACKET
VALIDATION_FAILURE
LOW_QUALITY_OUTPUT
UNCLASSIFIED_FAILURE
```

A generic HTTP error, slow response or model disagreement is not enough to infer quota exhaustion or provider unavailability.

## Attempt isolation

Every role attempt is bound to:

```text
ROLE_ATTEMPT_ID
AUTHORITATIVE_ROLE
ROUTE_AGENT
SELECTED_MODEL
SELECTED_VARIANT
MODEL_FAMILY
ATTEMPT_NUMBER
PACKET_SHA256
FROZEN_TARGET_SHA
FAILURE_CLASS
FALLBACK_STATUS
REPORT_COMPLETE
```

On eligible failure:

1. abort the failed attempt;
2. never consume its partial report;
3. preserve only non-secret attempt metadata;
4. keep packet bytes and frozen target unchanged;
5. select the next eligible independent route;
6. restart the complete role from the same packet;
7. accept only a report containing the current attempt ID, matching hashes and `REPORT_COMPLETE: YES`.

The fallback never continues a primary model response.

## Sticky attempt and primary re-entry

Once a fallback attempt begins, primary recovery does not interrupt it. The fallback finishes the complete role.

The primary becomes eligible again only for a later role invocation or later governed task after its cooldown expires. The next invocation is the health probe. There is no mid-role failback and no oscillation between candidates.

Cooldown uses provider `Retry-After` or an authoritative quota-reset timestamp when available. Otherwise the routing profile's bounded default cooldown applies.

## Same-model alternate providers

For provider outage, rate limit or plan quota exhaustion, the same model through another provider is preferred when configured.

For `MODEL_RETIRED` or `MODEL_UNAVAILABLE_ON_ALL_CONFIGURED_PROVIDERS`, all candidates from the retired/unavailable model family are skipped and the next different family is selected.

## Independence

Actual selected model families, not configured primaries, determine independence.

Default constraints:

- Implementation Reviewer differs from Executor when Executor family is known.
- Architecture Reviewer differs from Executor and the accepted Implementation Reviewer.
- Final Reviewer differs from Executor and both accepted reviewers.
- `MODEL_INDEPENDENCE_STATUS` is `PASS|DEGRADED|CONFLICT`.
- `allow_degraded_independence` defaults to false.
- With no eligible independent route, adjudication stops with `MODEL_INDEPENDENCE_CONFLICT`.

A candidate with `requires_role_rebalance: true` may be used only after every conflicting reviewer is rerun from its original frozen packet with an eligible non-conflicting family. The superseding report must pass the same attempt checks.

## State

No parallel evidence family is introduced. Attempt metadata is persisted in the existing task `RUN_STATE.json`, `.ai/STATUS.md` and existing reviewer/final reports. Incomplete output is not authoritative evidence.

## Failure budget

```text
FALLBACK_MAX_ATTEMPTS_PER_ROLE: bounded by configured candidates
FALLBACK_REPEAT_SAME_CANDIDATE: forbidden
FALLBACK_RECURSION: forbidden
```

Hidden fallback aliases have `task: deny`, preventing recursive delegation.

## Installation and compatibility

- No routing profile: existing 3.0.2 behavior and seven rendered agents.
- Routing profile: seven public agents plus generated hidden aliases.
- Installer validates schema, unique priorities, concrete variants, model families, trigger names and supported v3.1 roles.
- Installer writes a non-secret `opencode-governance-routing.json` manifest containing resolved candidates and managed aliases.
- Reinstallation removes only aliases listed in the previous manifest.
- Uninstall removes managed aliases and the manifest while preserving unrelated agents and provider authentication.

## Acceptance criteria

1. Legacy installation remains green on Windows and Linux.
2. A valid routing profile renders hidden aliases with correct model, variant and authoritative-role metadata.
3. Architect and Build may invoke only configured alias name patterns.
4. Every alias denies task delegation.
5. Invalid priorities, families, triggers, unresolved variants and unsupported roles fail closed.
6. Provider/quota failures prefer same-model alternate providers.
7. model-retired/global-unavailable failures skip the whole failed family.
8. partial reports cannot be accepted.
9. packet and target hash changes block fallback.
10. fallback attempts are sticky and primary is reconsidered only on a later invocation.
11. actual-family independence is checked before Architecture and Final review.
12. `requires_role_rebalance` never silently accepts a conflicting review set.
13. Windows and Linux CI cover install, verification, generated aliases, legacy compatibility and conservative uninstall.
